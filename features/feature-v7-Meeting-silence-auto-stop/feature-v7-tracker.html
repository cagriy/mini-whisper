Highlights

  • After 1 min with no transcribed speech (never in the first 3 min), a floating prompt counts down 1 min, then the meeting stops and is summarised.
  • Speech is a new non-empty partial or a non-empty segment; empty and repeated partials do not count.
  • Keep recording restarts the silence clock; Stop now is a manual stop; speech, pause, any stop, reconnecting or the setting turned Off close the prompt.

  • Settings → Meetings → Recording: "Stop after silence", Off · 1 min · 2 min · 5 min, default 1 min.
  • A silence stop sets the optional silenceStopSeconds on the meeting; its finished page shows a Flag chip "Stopped after N min without speech".

  • Test calls never prompt; older app versions read the new meetings unchanged.

Design: feature-design-v7-Meeting-silence-auto-stop.md

Accepted mockup: mockup-v7-overview.html#overview · published

Design language: DESIGN.md · specimen · published specimen

Summary

A meeting left recording after the call ends keeps transcribing whatever follows; two later calls once folded into one forgotten recording. Mini Whisper now watches a recording meeting for transcribed speech, offers to keep recording after a silent stretch, and stops the meeting a minute later when nobody answers.

Goals and non-goals

  • A forgotten recording ends about two minutes after the last words; a real quiet stretch costs one click.
  • The prompt is seen over any app without taking focus.
  • Not covered: audio-level detection, detecting a new call, splitting merged recordings, exports/CLI/MCP showing the stop, test calls.

Design

Components

ComponentResponsibility
SilenceWatch (new, core)Pure rules: grace 180 s, threshold, countdown 60 s, speech, keep, suspend, restart, expiry
SilencePrompt + MeetingEvent.silenceopen(minutes, secondsLeft) · closed · expired
MeetingControllerFeeds the watch from partials, segments, connection, ticker, pause, resume, stop; keepRecording(), stopAfterSilence()
Config.meetingSilenceStopSecondsmeeting_silence_stop_seconds ∈ {0, 60, 120, 300}, default 60
Meeting.silenceStopSecondsOptional; set only by a silence stop
SilencePromptModel / View / Panel / Controller (new, app)The floating card, its countdown and placement
MeetingCoordinatorRoutes .silence to the panel; stopAfterSilence() shares stop()'s bookkeeping
Chip, MeetingWindowModel, FinishedPageFlag chip variant with a leading symbol
SettingsModel, MeetingsSectionThe "Stop after silence" row

Prompt

  • Dialog card (380 pt, radius.card, color.card, color.line border, shadow.dialog), no scrim, in a borderless non-activating .floating panel on all Spaces and full-screen; first click acts.
  • Centred on the front app's display, top at 20% of its height.
  • Eyebrow: resting recording bars + "Recording · <title>". Title: "No one has spoken for N minute(s)". Body: "Recording stops in M:SS unless you keep it going." 4 pt depleting meter.
  • Buttons: Stop now (outlined, red label), Keep recording (filled accent).

Control flow

  • Tick opens the prompt when recording, not a test call, threshold > 0, meeting time ≥ 180 s, silent ≥ threshold, not reconnecting.
  • Each tick re-sends the seconds left; at 0 .expired → coordinator hides the panel and calls stopAfterSilence() → field saved, meeting stopped and summarised.
  • Resume restarts the clock with no new grace; .connected after reconnecting does the same.
  • Threshold read every tick: Off closes an open prompt; other changes apply to the next prompt.

Compatibility

Optional field, schema unchanged; 0.7.0 and earlier ignore it. Config key always written. On by default; CHANGELOG names the setting.

Testing

SilenceWatchTests (pure), MeetingControllerSilenceTests on VirtualClock, ConfigCodingTests, MeetingModelTests, and app tests for the prompt model, placement, coordinator routing, chips and settings; manual check over a full-screen app.

Risks

  • A real silent stretch left unanswered stops the meeting — grace, one-click Keep, 2/5 min/Off.
  • First click on a non-activating panel swallowed — acceptsFirstMouse, manual check.
  • Remote call without system-audio permission prompts during the other side's monologue — existing hint, Keep.
  • Background noise transcribed as speech keeps a forgotten recording going — today's behaviour, no worse.

Rollout

Next release, on by default at 1 min; Off restores today's behaviour. After implementation, /design-language-update turns decisions 72 and 73 active.

Plan: feature-plan-v7-Meeting-silence-auto-stop.md

Overview

Nine stages. The core rules (key, meeting field, SilenceWatch) and the self-contained prompt surface land first and in parallel; the controller then emits .silence; the setting and the chip follow; the coordinator turns the feature on in Stage 8; documentation closes. Every stage leaves both suites green and the app building, and each intermediate state behaves as today.

Stages

Stage 1 — The meeting_silence_stop_seconds key

0, 60, 120 or 300; default 60; anything else, wrong types included, reads as 60; always written. MWConfig/Config.swift, ConfigCodingTests, ConfigStoreTests.

Stage 2 — Meeting.silenceStopSeconds

Optional meeting.json field, omitted when unset; Markdown goldens unchanged. MWMeetings/MeetingModel.swift, MeetingModelTests, MeetingMarkdownTests.

Stage 3 — SilenceWatch and SilencePrompt

Every R2–R7 rule as a pure value type, tested with times as arguments. New SilenceWatch.swift, SilencePrompt in MeetingEvent.swift, new SilenceWatchTests.

Stage 4 — The floating prompt

Model, view, non-activating panel and controller under App/Meeting/SilencePrompt/; the Dialog card chrome moves into a shared .dialogCard(); new SilencePromptModelTests, SilencePromptControllerTests.

Stage 5 — The controller feeds the watch

.silence events, pause/resume/stop/reconnect handling, the ticker check, keepRecording(), stopAfterSilence(), the three log lines. MeetingController.swift, MeetingEvent.swift, MeetingWindowModel.apply no-op, new MeetingControllerSilenceTests.

Stage 6 — The setting

SettingsModel.setMeetingSilenceStop, silenceStopDescription, the row in MeetingsSection.

Stage 7 — The Flag chip

Chip gains .flag and a leading symbol; chips becomes [HeaderChip]; FinishedPage.head.

Stage 8 — The coordinator

Routes open/closed/expired to SilencePrompting; stopAfterSilence() shares stop()'s bookkeeping; AppDelegate passes the real controller; manual acceptance over a full-screen app, light and dark.

Stage 9 — Documentation

CHANGELOG.md, README.md Meetings section, CLAUDE.md module map.

Cross-cutting concerns

  • Security: the config value is validated; logs carry times and reasons, never transcript text (tested); the panel never becomes key.
  • Performance: one cached config load per tick; O(1) watch; the panel is made once and reused.
  • Observability: "silence prompt shown after N s", "silence prompt closed (reason)", "meeting stopped after silence (N s)"; a VoiceOver announcement on open.
  • Compatibility: optional field, schema 1; config key always written; no release between Stage 6 and Stage 8.

Planning decisions taken

  • Design §5.2 vs R1: the key decodes with try?, so a wrong type reads as 60 instead of resetting the whole config (design corrected).
  • Design §5.1: the recorded threshold is the expired prompt's (promptMinutes × 60), per R4 with R7 (design corrected).
  • Design §5.3: the non-recording backstop hides only for the session that opened the prompt; opening a stored meeting no longer hides a live countdown (design corrected).
  • SilenceWatch exposes read-only isSuspended, promptMinutes, lastSpeech.
  • .silence lands with the controller and apply's no-op in one stage; SilencePrompt lands with the watch.
  • Shared .dialogCard() extracted from DSDialog; injectable screen, announce and panel factory on the prompt controller; placement tests in SilencePromptControllerTests.
  • tick(to:) hoisted onto the shared MeetingHarness; bounded event lists and time limits in the new suites.
  • README and CLAUDE.md updated alongside the CHANGELOG; decisions 72 and 73 flipped by /design-language-update after the plan.
