Detail

Accepted mockup: Overlay — Side by side · published artifact

Summary

The recording card shows one animation today, the 24-dot constellation. This feature ports the five alternatives from the animation studies mockup into the app as selectable overlay styles, makes Soft meter the default, and adds a Settings → Overlay pane with a radio list and a looping in-window preview. The studies found the constellation's shifting link density competes with the transcript; the alternatives are quieter.

Goals and non-goals

  • Goals: six styles driving the same 300×300 card through every mode; Soft meter default; Overlay pane as the accepted mockup; the choice persists in config.json and applies at the next show; deterministic, AppKit-free motion tests plus scripted render tests.
  • Non-goals: caption bar, card geometry and error behaviour unchanged; no preview controls; no live swap while the card is visible; the mockup's Node test is not run in CI (its assertions are ported); no per-style tuning UI.

Design

Architecture

MWOverlaySim gains OverlayStyle, LevelSmoother and Choreography (extracted from ConstellationSimulation), StylePhase, StyleGeometry (fixed capacity 480 points), StyleSampler (pure port of Motion.sample), StyleSimulation, StyleFrame and PreviewScript. MWConfig gains Config.overlayStyle (default softMeter) with the unrecognised-raw round-trip pattern, and a dependency on MWOverlaySim. The app gains an OverlayAnimator protocol with ConstellationAnimator and StyleAnimator, CardChrome (shared card, label and error drawing), StyleLayer, an OverlayPreviewView/OverlayPreview pair, OverlayStyleCatalog, OverlaySection and Section.overlay.

Data

One key, overlay_style, raw values constellation, silk_ribbon, resonant_halo, soft_meter, liquid_pearl, petal_iris. Absent → soft_meter. Unknown → soft_meter at runtime, raw preserved on save until a style is chosen. New constants: point capacity 480, blend rate 9 s⁻¹, check 0.35 s, reduce-motion sample time 1.3 s, preview loop 13 s (2 / 6 / 3.5 s phases), preview voice level 0.65.

Interfaces

Settings → Overlay: SettingsPane with an HStack — a 214 pt list of radio rows in the General pane's engine-row form (names only, the selected row unfolds its summary, "Default" capsule on Soft meter; order Soft meter, Silk ribbon, Resonant halo, Liquid pearl, Petal iris, Constellation) beside a 316×316 rounded well (underPageBackgroundColor, 1 pt separator border) holding the 300×300 preview; footnote "The card appears beside the text field you are dictating into. The preview replays a short dictation with a simulated voice." SettingsModel gains overlayStyleRows, selectedOverlayStyle and setOverlayStyle(_:). OverlayPanelController gains init(style:reduceMotion:) and setStyle(_:).

Control flow

show(on:) rebuilds the animator when the stored style differs from the current one and swaps the sublayer; ticks step the animator and hide on isFinished. StyleSimulation.step clamps dt, advances the choreography, smooths the level with the app's existing one-pole while recording, samples the style and blends the geometry toward the sample with 1 − e^(−9·dt); done draws the check over 0.35 s. AppDelegate.apply(config) forwards the style to the panel controller and logs a change. The preview view starts a display link when attached to a window, replays PreviewScript (starting 0–2 s, recording 2–8 s with simulatedRMS, processing 8–11.5 s, result at 11.5 s, re-show at 13 s) and stops on detach or dismantle; a style change rebuilds the animator and restarts the loop.

Failure and edge cases

  • Unknown overlay_style: Soft meter shown and used, raw kept until a row is clicked. Wrong JSON type: the file is treated as corrupt exactly as today.
  • Style changed while the card is visible: current animation finishes; new style at the next show.
  • Reduce Motion: fixed sample time 1.3 s, level snaps, no blend, check at once; fades and no-shake unchanged.
  • Error in a new style: shake with the marks drawn, then marks hidden and the message shown, then hide, identical to the constellation.
  • Preview with Settings hidden: driver stopped on window detach; NSView.displayLink pauses off-screen.

Security and performance

The only input is a user-writable config value decoded into a closed enum. At most 480 points per frame, buffers allocated once per animator, the pearl's CGGradient created once per layer. No new permissions; the preview never touches the microphone.

Testing

OverlayStyle, LevelSmoother and Choreography suites (the constellation suite unchanged and green); StyleSampler tests ported from animation-studies.test.cjs (intensity response, processing and quiet ignore level, finite geometry inside [5,295]×[5,275], done emits nothing); StyleSimulation (phase mapping, blend, check progress, reduce motion, dt clamp, finish timings); PreviewScript boundaries and simulated RMS; Config round-trip; StyleLayer 600-frame scripted render per style; animator factory; preview view start/stop/wrap; catalog; SettingsModel section order, write-through and refresh. Manual acceptance compares each preview with the studies mockup.

Risks

  • Fidelity drift from the mockup — formula table and ported assertions; side-by-side acceptance.
  • Preview display link outliving the pane — stop on detach and dismantle, unit-tested.
  • The animation-studies mockup and its test are untracked — Stage 1 commits them.
  • Choreography extraction changing constellation behaviour — the existing suite stays untouched.
  • Check mark brief at 260 ms — accepted by decision.

Rollout

Single release, no flag. Stages: spec files; OverlayStyle + config; LevelSmoother and Choreography extraction; StyleSampler; StyleSimulation + PreviewScript; CardChrome, StyleLayer, animators, panel controller; Settings section, catalog, preview; AppDelegate wiring, CHANGELOG, CLAUDE.md. Older builds ignore the key.

Detail

Overview

Six selectable overlay styles for the 300×300 recording card, five of them ported from the animation-studies mockup, with Soft meter as the new default and a Settings → Overlay pane that picks between them beside a looping live preview. The plan lands bottom-up along the module graph: the config key first, then the two behaviour-preserving extractions the new styles share with the constellation, then the pure motion model, then drawing, then the animator seam that makes the card honour the stored style, then the Settings pane and its live preview plus the release notes. Design §9's rollout order is followed, with three regroupings recorded as planning decisions. Every stage leaves swift test and xcodebuild … test green and the app building.

Observed baseline (2026-09-07, all green): swift build exit 0; swift test → 480 tests in 50 suites; xcodebuild … test → 105 tests in 16 suites, ** TEST SUCCEEDED **.

Cross-cutting concerns

  • Security — the only new input is overlay_style, decoded into a closed enum with a default fallback; a wrong JSON type falls into ConfigStore's existing corrupt-file path. No secrets, network, permissions or new trust boundaries at any stage; the preview never opens the microphone.
  • Performance — StyleGeometry allocates its 480-point buffer once, StyleSimulation owns two, StyleLayer copies element-wise into a third and builds its CGGradient once. Stage 3 pins the 480 ceiling; Stages 4 and 5 pin the no-reallocation invariant.
  • Observability — one addition: Log.ui.info("Overlay style: …") at start and on every change, in Stage 6.
  • Compatibility — no migration; older builds and the Python line ignore and preserve the key. One intermediate window, between Stages 6 and 7: the default becomes Soft meter with no in-app picker yet. Accepted rather than bundled — design §9 cuts a single release, so no build ships from inside that window.

Verification

Both suites green; Settings → Overlay in the right place and not scrolling; each of the six styles compared side by side against mockup-v1-animation-studies.html's cards; a dictation per style; the error card's shake-then-message; a deleted key and a nonsense key both resolving to Soft meter with the raw value preserved; Reduce Motion drawing static frames; the preview's display link stopping when Settings closes; and the CHANGELOG, CLAUDE.md and spec files all committed.

Planning decisions taken

  1. Design §5.12's MWConfigTests/ConfigTests does not exist — the suite is ConfigCodingTests.swift. Corrected in the design file; a factual grounding error, not a scope change.
  2. Choreography.init(reduceMotion:) — §5.1's interface omits the input its shakeOffset needs; closed as an under-specification, matching ConstellationSimulation's shape.
  3. OverlayPreviewView takes an injected driver factory defaulting to the real DisplayLinkDriver, plus an internal tick(_:), so R14's start/stop assertions run without a CADisplayLink.
  4. AppDelegate wiring lands in Stage 6 with the animator seam rather than in a final stage, so R3 is live the moment its stage merges.
  5. Design §9's "commit the spec files" stage is folded into Stage 1 — a git add of two documentation files is not a reviewable increment.
  6. R16 is split: CLAUDE.md in Stage 1 where the module edge lands, the CHANGELOG in Stage 8 when the feature is complete.
  7. File placement follows the existing Frame.swift convention — the design specified types, not files.
  8. New Constants land in the stage that first needs them — Styles in Stage 3, Preview in Stage 4.
  9. SettingsView's "seven sections" doc comment is corrected to eight in Stage 7.
  10. OverlayStyle.default is declared with backticks, as URLSessionConfiguration.default is, keeping the design's spelling at every use site.
