Detail

Summary

Mini Whisper (Python/PyObjC v0.1.8) is rebuilt as a native Swift macOS app that replaces the Python app in place — same bundle ID, config, Keychain, cask and release pipeline. It reproduces every user-visible behaviour, adopts an idle-stop audio-engine lifecycle because the source repo's own analysis shows the ~0.5 s press→record delay is architectural (none of its six fixes were applied), corrects latent defects, and adds local history with a vocabulary list and per-app cleanup profiles. The source repo is read-only.

Scope — in

  • Drop-in identity: com.ips.mini-whisper, ~/.config/mini-whisper/, Keychain service mini-whisper (openai / elevenlabs / speechmatics keys), usage and pricing_overrides preserved.
  • Full v0.1.8 parity including the source's edge-case guards (0.3 s hold threshold, 0.5 s / RMS 0.005 gate, HTTP error messages, 5 s stream finish timeout, 60 s pre-connect cap, segment-restart heuristic, Speech permission on first on-device use).
  • Idle-stop engine lifecycle; event-driven hotkey→overlay path; warm press→recording < ~50 ms.
  • macOS 14 floor; SpeechAnalyzer engine on macOS 26+ and default there.
  • Settings redesign making invalid states unrepresentable; new controls for retention, vocabulary, profiles, toggle cap.
  • Defect fixes: clipboard restore, overlay follows active display, no billing for discarded dictations, single-instance guard, toggle cap (default 5 min).
  • Key-free operation via on-device engines.
  • History (0–30 days, default 7) with History window; manual vocabulary list; per-app profiles (cleanup prompt, cleanup on/off, submit key).
  • Overlay: same physics plus native polish, 3–4 alternatives from /feature-design.
  • Unit tests (TDD); CI pipeline equivalent to the source (sign, notarise, DMG, release, cask); version continues at 0.2.0; private repo cagriy/mini-whisper-swift.

Scope — out / deferred

  • Toggle-mode visual indicator (overlay persistence is the cue).
  • Caption feedback for silent key-less fallback (superseded by Settings gating).
  • Pricing overrides UI.
  • Per-app transcription instructions; built-in profile presets.
  • Automatic / edit-driven vocabulary learning.
  • Live typing into the target app; clipboard-free Accessibility insertion; Shortcuts/CLI service.
  • Any change to the Python source repo.

Technical direction (constraints)

  • Native Swift, no bundled runtime; signed, notarised Apple-Silicon DMG.
  • Read/write existing config files and Keychain items unchanged; new keys added with defaults so the Python app can still read the file.
  • Audio engine started once, stopped after idle; survives device/route changes; mic indicator only while running.
  • No polling on the hotkey→overlay path; overlay pre-built and warm; sounds pre-loaded.
  • Overlay holds 60 fps without per-frame heap churn; physics constants fixed by the source.
  • Global hotkeys with modifier-only triggers, key capture, missed key-up recovery; permissions limited to Microphone, Accessibility, Speech Recognition.
  • Paste targets the frontmost app's pid; clipboard restored afterwards.
  • Streaming engines speak the wire protocols pinned in the source; Python fixtures may be copied into tests.
  • History and vocabulary stored locally only; retention 0 writes nothing.
  • Tests for the non-UI pipeline; UI verified manually.

Summary

Native Swift menu-bar app replacing the Python app in place. Reproduces every user-visible behaviour, adopts an idle-stop audio lifecycle and event-driven UI for latency, fixes five latent defects, gates Settings on key presence, adds history, vocabulary and per-app profiles. Goals and non-goals

  • Drop-in upgrade with TCC and Keychain continuity; behavioural parity with v0.1.8.
  • Warm press→recording < 50 ms; 60 fps overlay without per-frame allocation.
  • Key-free operation via on-device engines; invalid Settings states unrepresentable.
  • Out: Python repo changes, deferred storm items, Intel builds.

Architecture

xcodegen project.yml → app target; Packages/MiniWhisperCore with modules MWConfig, MWHotkeys, MWAudio, MWStreaming, MWTranscription, MWPipeline, MWUsage, MWHistory, MWProfiles, MWPaste, MWOverlaySim, MWSupport. Platform adapters in the app implement Core protocols (key events, audio tap, key posting, pasteboard, sounds, clock).

Key components

  • HotkeyMatcher — pure state machine reproducing the source grammar and matching rules; watchdog now covers modifier-trigger bindings.
  • AudioCaptureEngine actor — engine lifecycle, idle stop, config-change and sleep handling, RMS, buffer fan-out.
  • WebSocketEngine + three adapters, SFSpeechEngine, SpeechAnalyzerEngine, EngineFactory with downgrade rules.
  • DictationController (main actor) — press/release, hold threshold, toggle cap, generation guard, billing, history.
  • ConstellationSimulation — deterministic physics and choreography; ConstellationLayer draws it.
  • Paster — pasteboard snapshot/restore, CGEventPostToPid, submit-key variants, AX check.

Data

  • config.json superset: history_retention_days, idle_stop_seconds, toggle_max_seconds, speech_model_prompted, vocabulary, profiles; unknown keys round-trip; atomic writes.
  • history.jsonl (0600) with id, ts, text, app, bundle id, engine, seconds, cost.
  • Keychain generic passwords, service mini-whisper, login keychain.

Failure handling

Every engine failure degrades to the next engine or batch; device change ends the recording with an error; stale jobs stop before the next API call; Accessibility loss surfaces as an overlay error; clipboard restored only if unchanged.

Testing

Swift Testing per module with fakes and fixture replay; app smoke tests via xcodebuild; opt-in integration tests against OpenAI; manual acceptance checklist covering upgrade-in-place, latency, engines, profiles, history, displays, sleep/wake.

Risks

  • TCC / Keychain first-launch prompts.
  • SpeechAnalyzer behaviour and asset download.
  • Swift 6 concurrency around AVAudioEngine and Speech callbacks.
  • Clipboard restore timing in slow targets.
  • Provider protocol drift.

Rollout

Core modules with tests → v0.2.0-beta.1 pre-release installed over 0.1.8 for acceptance → v0.2.0 tag updates the cask (URL, homepage, macOS ≥ Sonoma). Rollback via the 0.1.8 DMG; config compatible both ways.

Cross-cutting concerns

  • Security — secrets only via SecretStore; no key or transcript text at INFO (asserted with a capturing log sink); ephemeral URLSession and pinned vendor URLs; synthetic key events only to the resolved pid after the Accessibility check; history file 0600 and retention 0 leaves no file; hardened runtime, Developer ID, audio-input entitlement only.
  • Performance — .starting emitted before the first await (tested); flag-flip capture and 1024-frame tap; config/secrets cached; preallocated overlay frame with reuse asserted; caption redraw on change only; no polling timers in the controller.
  • Observability — Log categories and levels; press→live, finish, transcribe and clean timings at INFO; engine selection reasons; billing summary; --debug file sink; About shows the version.
  • Compatibility / migration — config.json superset with unknown-key round-trip and the daily_usage migration; Keychain unchanged; bundle ID, Team ID and install path unchanged; cask raised to Sonoma and repo switched by the release job; rollback to 0.1.8 documented. The repo is buildable and green after every stage.

Planning decisions taken

  1. Test convention (greenfield): Swift Testing, one test target per module, shared fakes in Sources/MWTestSupport, fixtures inside the owning test target (shared WAVs under MWTestSupport) via Bundle.module; AppTests for app-only tests.
  2. xcodegen: target MiniWhisper with PRODUCT_NAME "Mini Whisper", PRODUCT_MODULE_NAME MiniWhisper, explicit TEST_HOST/BUNDLE_LOADER on AppTests (observed failure without it).
  3. Design fact correction: AnalyzerInputConverter does not exist in the macOS 26.5 SDK — design now uses AVAudioConverter into bestAvailableAudioFormat wrapped as AnalyzerInput(buffer:).
  4. Design under-specification closed: beginCapture() + attachListener(_:) after engine.start(sink); pre-attachment buffers recorded but not streamed.
  5. Design contradiction resolved by §3 precedence: processing order is stale check → bill → paste → append history (F15, F29 win over §5.5 prose).
  6. Pipeline split: ProcessingJob (Stage 20) before DictationController (Stage 21).
  7. Protocol seams with fakes for every platform API (AudioBackend, SecItemAPI, SpeechRecognitionAPI, SpeechAnalyzerAPI, HTTPTransport, WebSocketConnection, KeyPoster/PasteboardAccess/AccessibilityCheck/ProcessCheck, FrontmostAppProviding).
  8. Opt-in integration tests gated by MW_INTEGRATION=1 (and OPENAI_API_KEY); the OpenAI fixture test asserts non-empty output without the source's LLM judge.
  9. CaptionModel placed in MWOverlaySim so caption rules are host-tested.
  10. CI in two steps: tests + unsigned build in Stage 1; signing, notarisation, release and cask in Stage 30 verified by workflow_dispatch.
  11. Stage order follows design §9: Core in dependency order → app surfaces one per stage (dictating app at Stage 24) → beta → release.
