Summary

A scripted remote meeting that measures transcription quality on this Mac with a chosen engine. Two synthetic voices, played by macOS say in separate processes, are captured by the system-audio tap like the far side of a real call; the user reads their lines from a script pane. At Stop the transcript is scored against the script and the score is kept with the meeting.

Goals and non-goals

  • Goals: two-click start; the real remote path end to end; objective WER, label and latency scores; runs kept and compared per scenario revision; invisible to agents.
  • Non-goals: in-room test calls, generated content, rescoring after edits, unattended runs, cross-run charts.

Stop order

Conductor end (say terminated, running line stopped, rest not reached) → controller.stop(summarise: false) → finishTest (score, write testcall.json, set WER, emit) → summarise. The quit path skips the summary.

Scoring

Done lines only. Transcript words are assigned to lines by padded time windows; overlaps resolve by token match, then nearest span. Per-line alignment gives S/D/I; roles sum to WER. Clean labels need purity ≥ 95% and a unique majority label. Latency runs from line end to the arrival of the final segment holding the last matched word.

Security

say runs by absolute path with an argument array; voice names are allow-listed; testcall.json is 0600; agents cannot reach test meetings; no script or transcript text is logged.

Risks

  • TTS mispronunciation counted as engine error: listening pass while authoring, revision bump on change.
  • Default voices differ across macOS versions: substitution and a disabled state with instructions.
  • Voices not captured (TCC, routing): unavailable banner plus a per-line capture check.
  • Depends on the uncommitted ducking and leveller fix: shipped first.

Rollout

Next minor release (0.6.0), no flag. Order: ducking fix, model/store/agent filter, normaliser/aligner/scorer/scenarios, conductor, controller, App surfaces. README section and CHANGELOG entry.

Overview

Four layers, bottom up, with the app working after every stage. Foundation (Stages 1–3), independent components in two parallel batches (Stages 4–10), the controller (Stages 11–12), then the App surfaces (Stages 13–17). The Test Call… entry point lands in Stage 16, after the session, script pane and score pane exist.

Stages

Stage 1 — Land the in-tree ducking and leveller fix

Non-TDD (integration-verified): verify and commit the uncommitted fix the test call measures. Touches AVAudioEngineBackend, MeetingAudioPath, SystemAudioLeveller and its tests, CHANGELOG, README, CLAUDE.md.

Stage 2 — Test-call tag, score record and store support

TestCallTag, TestCallRecord (schema 1), optional test on Meeting and IndexEntry, MeetingStore write/read of testcall.json (0600), tag copied into index rows. Touches MWMeetings model and store, MeetingFixtures, MWMeetingsTests and two legacy fixtures.

Stage 3 — MWTestCall module, value model, normaliser and aligner

Registers the module in Package.swift and project.yml, adds the shared value types, TranscriptNormalizer (R14) and WordAligner (R15), and the say -v ? fixture.

Stage 4 — Hide test meetings from agents

AgentMeetings decorator in MWAgentAccess; App/AgentCommand.swift passes it to the CLI and MCP server (R22).

Stage 5 — Voice casting and run history

VoiceCatalog (parse, English filter, substitution, allow-list) and TestRunHistory (latest WER per current revision, runs newest first, capped at 50).

Stage 6 — Scenario catalogue

The 8 bundled scenarios, revision 1, with pick(.random | .named) under an injected RNG.

Stage 7 — Test-call conductor

Clock-driven script driver: say lines, 1.2 s hand-over, 20 s skip, 30 s cap, Skip, Overlap, Stop, sleep, say failures, capture check.

Stage 8 — Meetings list: TEST chip and test meta

MeetingsListModel row flag and R23 meta line, TestTag view, list chip.

Stage 9 — Test-call scorer

Per-line windows, alignment and heard, WER per role and overall, labels, purity, clean, cross-credited counts, latency.

Stage 10 — say player and system voices

SayProcessPlayer and SystemVoices in App/TestCall, unit-tested with stand-in executables; opt-in integration checks that say exits normally and the tap hears it.

Stage 11 — Controller: test-meeting plumbing

start(engine:test:), meetingTime, userSpeech, lastAudibleSystemAudio, segment arrivals, Pause no-op, .testScore on open; MeetingControlling and StubController move with it.

Stage 12 — Score at Stop: finishTest

Score, write testcall.json, set the tag's WER, emit .testScore; MWMeetingPipeline gains the MWTestCall edge.

Stage 13 — Test-call session and coordinator wiring

TestCallSession, the Stop order (end → stop(false) → finishTest → summarise), quit and sleep routing, coordinator startTestCall.

Stage 14 — Script pane during the call

TestCallPaneModel script half, ScriptPane, TEST chip and disabled Pause in the header, labelling note on the source line.

Stage 15 — Score pane and Earlier runs

Head block, line badges, expandable rows with transcript highlight, R20 messages, Earlier runs sheet.

Stage 16 — Setup page and the Test Call… entry point

Chooser link, TestCallSetupView (Scenario, Engine, Overlap), voice gating; manual end-to-end run against the accepted mockups.

Stage 17 — Documentation and acceptance

README Test call section, CHANGELOG Added entry, acceptance per engine, listening pass, agent checks.

Cross-cutting concerns

  • Security: say by absolute path with an argument array; no line starts with "-"; voice names allow-listed before casting and launch; testcall.json 0600; the agent filter lands in Stage 4, before any stage can create a test meeting.
  • Performance: 100 ms main-actor poll; per-line alignment on ~15 tokens; scenario menu reads index.json only; Earlier runs loads ≤ 50 records off the main actor.
  • Observability: start, skipped, voice substituted and scored log lines carry ids and outcomes only, each with a no-text test.
  • Compatibility: optional fields, no migration; defaulted parameters keep every call site; protocol and stub change atomically.

Verification

Run a test call from the chooser per engine; check the score pane, list row, search hit and Earlier runs; reopen shows the same pane; mini-whisper meetings list, search and transcript never return a test call; an interrupted run shows "No score: the test call did not finish."; core and app suites green.
