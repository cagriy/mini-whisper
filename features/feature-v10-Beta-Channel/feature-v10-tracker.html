Detail

Accepted mockup: Segmented update channel · artifact · DESIGN.md · specimen (artifact)

Summary

Users choose Release (default) or Beta in Settings. Release users see release versions only; Beta users also see betas. One appcast.xml; beta items carry Sparkle's channel element and the app allows the beta channel only when opted in. The pipeline learns the X.Y.ZbN format, marks betas as GitHub prereleases and keeps them out of Homebrew.

Goals and non-goals

  • Opt-in betas, Release by default, one pipeline, correct Sparkle ordering (0.8.2 < 0.9.0b1 < 0.9.0b2 < 0.9.0).
  • Not: downgrades, rc or other channels, betas through Homebrew, a second feed, 0.8.x hotfixes after 0.9.0b1.

Design

Components

  • MWConfig: UpdateChannel (release, beta) and Config.updateChannel under update_channel, unknown values kept like theme.
  • App: UpdateChannelPolicy (pure): sparkleChannels, isBeta(version), Tracker for change detection.
  • AppUpdater: UpdaterChannelDelegate.allowedChannels(for:); channelChanged() resets the cycle after a short delay.
  • AppDelegate.apply: sets the channel, logs and resets on change.
  • SettingsModel: updateChannel, chooseUpdateChannel, confirmBetaChannel, cancelBetaChannel, isBetaBuild; GeneralSection row; MainView DSDialog.
  • scripts/appcast.py: X.Y.ZbN accepted, beta channel element, --print-channel; build.yml gates prerelease and Homebrew on it.

Interface

Updates card rows: Automatically check for updates (version line, Beta chip on a beta build), Update channel (Release · Beta), Check for an update now. Beta dialog: "Switch to beta versions?" with Cancel / Switch to Beta.

Failure cases

  • Malformed tag fails the build before publishing.
  • Older clients (Sparkle 2.9.6) ignore beta items.
  • A bad beta is pulled from appcast.xml or replaced by the next beta.

Testing

ConfigCodingTests, UpdateChannelPolicyTests, SettingsModelTests, test_appcast.py; a manual Sparkle channel test with a doctored local appcast; R11 checks on the v0.8.2 and v0.9.0b1 tags.

Risks

  • Non-numeric CFBundleVersion trips a tool: local build check before the first beta tag.
  • Pipeline mistake leaks a beta: one tested channel source, gated Homebrew step, R11 checks.
  • Rebasing v9 conflicts in Config.swift, SettingsModel.swift, CHANGELOG, project.yml: resolve and run both suites.

Rollout

  1. v9 parked on v9-naming (done).
  2. Build v10 on main; verify locally.
  3. Release 0.8.2.
  4. Rebase v9-naming onto main; run suites.
  5. Release 0.9.0b1 to the beta channel; verify Beta and Release machines.

Detail

feature-plan-v10-Beta-Channel.md

Overview

Six stages on main (v0.8.1 plus its appcast commit, no v9 commit), bottom-up. First, in parallel, the update_channel key and the beta-aware appcast.py. Then, in parallel, the Sparkle wiring and the release-pipeline gates with their CLAUDE.md runbook. Then SettingsModel's channel state, and last the Updates card, the Dialog and the CHANGELOG entry, so the control appears only once everything behind it works. Releasing 0.8.2, rebasing v9 and tagging 0.9.0b1 are operator steps after Stage 6.

Stages

Stage 1 — update_channel in Config (TDD)

Config reads and writes update_channel as a closed UpdateChannel, with theme's round-trip rules. It opens with a read-only gate that main holds no v9 commit. Touches Sources/MWConfig/UpdateChannel.swift (new), Sources/MWConfig/Config.swift, Tests/MWConfigTests/ConfigCodingTests.swift.

Stage 2 — Beta versions and channels in appcast.py (TDD)

Accepts X.Y.ZbN (N ≥ 1), writes <sparkle:channel>beta</sparkle:channel> into beta items, and adds --print-channel. A guard rebuilds the published 0.8.1 item byte for byte. Touches scripts/appcast.py, scripts/tests/test_appcast.py.

Stage 3 — Sparkle channel filter and change reset (hybrid)

The pure UpdateChannelPolicy (sparkleChannels, isBeta, Tracker) is test-first. The wiring: a statically retained SPUUpdaterDelegate returns the allowed channels, and AppDelegate.apply sets the channel, then logs and resets the cycle on a change after launch. Touches App/UpdateChannelPolicy.swift, AppTests/UpdateChannelPolicyTests.swift, App/AppUpdater.swift, App/AppDelegate.swift.

Stage 4 — Release pipeline per channel, and its runbook (non-TDD, config-only)

"Resolve version" derives the channel and fails a malformed tag; beta tags make prereleases and skip Homebrew. CLAUDE.md documents the format, the per-channel table, the CHANGELOG convention and pulling a bad beta. Verified by a YAML parse and by simulating the step under four refs. Touches .github/workflows/build.yml, CLAUDE.md.

Stage 5 — Channel choice in SettingsModel (TDD)

updateChannel, confirmingBetaChannel, chooseUpdateChannel, confirmBetaChannel, cancelBetaChannel, and isBetaBuild through an injectable appVersion. Touches App/Settings/SettingsModel.swift, AppTests/SettingsModelTests.swift.

Stage 6 — Updates card, Beta dialog, CHANGELOG (platform-only / UI wiring)

The channel pill as row 2, the Beta chip on a beta build, and the Dialog in MainView's chain, cancelled on navigation. Verified by build, the suites and manual checks, including a 0.9.0b1 build. Touches App/Design/SettingRow.swift, App/Settings/GeneralSection.swift, App/Main/MainView.swift, CHANGELOG.md.

Cross-cutting concerns

  • Security: no new trust boundary; a closed enum; the delegate returns only [] or ["beta"]; same signing and notarisation for betas; only the channel name is logged. No tag is pushed until every stage lands.
  • Observability: one Update channel line per change; the CI job summary shows version and channel.
  • Compatibility: an additive key with no migration; byte-identical release items; the defaulted appVersion keeps every construction site compiling; the key is inert until Stage 3, and the control appears only in Stage 6.

Verification

  • Core, app and script suites green (baselines 1305, 519, 14).
  • Manual Sparkle check against a doctored local appcast: Release offers 0.8.3 only; switching to Beta offers 0.9.0b1 without Check Now; back on Release, 0.9.0b1 is not offered.
  • Post-plan: release 0.8.2 (normal release, Homebrew bump, no channel element); rebase v9; tag 0.9.0b1 (prerelease, no tap commit, beta item).

Planning decisions taken

  • The appcast pattern is (b[1-9]\d*)?: §3 R9's N ≥ 1 outranks §5's (b\d+)?, which was corrected in place.
  • Beta version line in two lines (version and chip, then the sentence), through a new view-builder SettingRow initialiser: SwiftUI Text on macOS 14 cannot hold a view.
  • The delegate is retained by a static let, because Sparkle holds delegates weakly.
  • UpdateChannel gets its own file, as AppTheme does; the byte-identity guard uses the published 0.8.1 item; the CLAUDE.md runbook rides with the CI stage and the CHANGELOG entry with the UI stage.
  • Design facts corrected in place: the project.yml anchors; the test harness uses a real temp-directory ConfigStore; an out-of-process config edit reaches apply only with the next in-app write.

Deviations from the design

None — the plan matches design v10.
