Mockup — not shipping code · Feature v4 · “Export Files” · Accepted 2026-11-09

What the two Export buttons write: a transcript file and a summary file, each shown as the raw Markdown on the left and as a Markdown viewer renders it on the right. Both open with YAML front matter so agents and scripts can read the facts without parsing prose; both carry the meeting's id so they tie back to the CLI and MCP server. What to judge: the speaker-line format, how notes, gaps and pauses appear inline, the front matter fields, the summary file's Notes section and footer, and the file names. Design language: plain CommonMark that renders the same in GitHub, Obsidian, Bear and Xcode's Quick Look — no HTML, no tables, no emoji.

File 1 · Northwind rollout sync - transcript.md

One paragraph per merged speaker segment: the bold name and the meeting time on their own line, the words on the next. A viewer runs them together into one line; grep and agents see the name first. Notes, connection gaps and pauses are block quotes in time order. File names are the title with “/” and “:” replaced by “-”.

Rules the files follow

  • Front matter values that could be read as numbers or times are quoted; speakers lists names in order of first appearance; mode is remote or in-room.
  • Speaker lines use the names as renamed in the app; a speaker never renamed stays Speaker 2. Times are meeting time, hh:mm:ss from Start, so they match the window and the CLI.
  • A transcript export without any summary is still complete; a summary export is refused with a message when the meeting has no summary.
  • Export both writes the two files side by side in the chosen folder; the summary's transcript key then resolves.
  • The CLI's mini-whisper meetings transcript <id> and summary <id> print exactly these files to stdout, so an agent and a human read the same text.
