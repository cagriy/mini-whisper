Detail

Summary

Mini Whisper records short dictations from the microphone and pastes the result into the front app. Users also sit in remote calls and in-room meetings where nobody keeps a reliable record, and the app already has the pieces a meeting recorder needs: audio capture, three cloud streaming adapters, Keychain-held keys, editable prompt files, a History window and per-day cost tracking. Meeting mode adds a hotkey or menu item that captures the microphone and the Mac's system audio, a window with the live transcript (the user's voice labelled as them, other voices as Speaker 1..N by real-time diarization, renamable at any point), a timestamped notes pane, and on Stop a Claude Sonnet 5.5 summary under an editable prompt. Transcript and summary export as Markdown, past meetings live in an in-app list, and a read-only command-line entry point and MCP server let agents fetch them. It is the meeting work the 2026-09 application review deferred, sized to the app's own strengths rather than to meeting bots or team workspaces.

In scope

  • Third configurable hotkey and menu items to start and stop a meeting; a Meetings… menu item.
  • Microphone plus system audio capture (macOS 14.2+; microphone only with a notice on 14.0/14.1), with onboarding and Settings for the new System Audio Recording permission.
  • Live meeting window: speaker-labelled transcript with times, user labelled from the microphone, Speaker 1..N from diarization, rename at any point, Pause/Resume, elapsed time, running cost.
  • Timestamped notes pane; notes appear in the exported transcript at their time and are passed to the summariser.
  • Two selectable meeting engines: Speechmatics (existing adapter) and AssemblyAI (new adapter, new Keychain account).
  • Summary on Stop by Claude Sonnet 5.5 through a new Anthropic Keychain account; shipped default prompt editable like the existing prompts; Re-summarise.
  • After Stop: edit transcript text and reassign segments to another speaker.
  • In-app Meetings list (open, rename, re-summarise, export, delete); meetings kept until deleted, outside the history retention window.
  • Audio kept per meeting, deletable, with a Settings toggle.
  • Export of transcript and summary as Markdown via the save panel.
  • Reconnect on a dropped connection with a marked gap; audio keeps recording.
  • Dictation hotkey locked during a meeting, with a notice.
  • Default title from date, time and front app; renamable.
  • Costs counted in the existing usage rows and overridable through pricing overrides.
  • Read-only agent access: CLI and hand-written stdio MCP server to list, fetch and search meetings.

Out of scope / deferred

  • Calendar integration; re-transcribe from saved audio; retroactive start; live running summary; on-device diarization; "ask your meetings"; agent start/stop control; auto-export folder; mark-moment hotkey.
  • Haiku 5.5 or an OpenAI model as summariser; Soniox, Deepgram, OpenAI, ElevenLabs or Apple as meeting engines; voice-profile speaker recognition across meetings.
  • Dictation during a meeting; editing text while recording; languages beyond the current adapter configuration; meeting bots, cloud sync, sharing, team workspaces.

Technical direction (constraints for design)

  • Bundle ID, Team, macOS 14 target, Swift 6 strict concurrency unchanged; Sparkle stays the only third-party dependency. AssemblyAI adapter, Anthropic client and MCP server are written on Foundation networking.
  • System audio via a native API available on 14.2+, graceful microphone-only fallback below it, no Screen Recording permission if an audio-only route exists.
  • Secrets only in Keychain as new accounts beside the existing three. config.json stays round-trippable with new keys for hotkey, engine, audio retention and summariser.
  • Meeting data (segments, notes, summary, audio, metadata) under ~/.config/mini-whisper/, never auto-deleted, single source for window and agent access.
  • User labelled from the microphone source, others by provider diarization; stream topology is a design decision with a cost consequence to surface in Settings and README.
  • Renames are a local mapping over stored segments; meetings are not bounded by the dictation toggle cap or idle stop; provider session limits handled without ending the meeting.
  • New pricing constants in the existing rate tables; every duration tested on the virtual clock; request-contract tests per provider; agent access read-only by construction.

Summary

A meeting mode for the menu-bar dictation app. A third hotkey or menu item opens a chooser between a remote call (microphone plus the Mac's own system audio) and an in-room meeting (microphone only). While recording, a window shows a live speaker-labelled transcript with the user's speech under the user's name and other voices as Speaker 1..N, a notes pane stamped with meeting time, elapsed time and running cost. Stop sends transcript and notes to Claude Sonnet 5.5 for a summary under an editable prompt. Meetings are stored under the config directory, listed in a searchable Meetings window, exported as two Markdown files, and readable by agents through a command-line tool and a stdio MCP server.

Goals and non-goals

  • Every segment carries a speaker and a time; the user's speech is labelled by name; renames apply everywhere and persist.
  • Summary on Stop; a meeting without one can be summarised later by one button. No re-summarise, no summary versions.
  • Dropped connections never end a meeting; gaps are marked; audio keeps recording.
  • Costs appear in Today/Month and stay overridable.
  • Deferred: two provider sessions per remote call, calendar integration, batch re-transcription, live running summary, on-device diarization, agent control of recording, other summarisers and engines, non-English meetings, consent features.

Data model

  • Config keys: meeting_hotkey (default ctrl+alt+cmd+m), meeting_engine (speechmatics_standard | speechmatics_enhanced | assemblyai_streaming | assemblyai_pro), meeting_keep_audio (default true), meeting_user_name, meeting_system_audio_explained.
  • meetings/index.json plus meetings/<uuid>/meeting.json, segments.jsonl (speaker id, start/end, text, words, session, provider label, turn order, edited, pinned), notes.jsonl, audio.m4a (AAC 16 kHz mono).
  • Speaker labels: id 0 is the user; (session, provider label) pairs map to numbered speakers; renames change the name only; rename-to-existing merges.
  • Pricing per minute: speechmatics 0.0075 (was 0.0067), speechmatics_enhanced 0.013333, assemblyai 0.0025, assemblyai_pro 0.0075, assemblyai_diarization 0.002; per MTok: claude-sonnet-5-5_in 2.00, _out 10.00.
  • Keychain accounts assemblyai-api-key and anthropic-api-key under the existing service.

Interfaces

  • Meeting window (920×620): chooser → recording (title, mode chip, capture chip, connection chip, elapsed, cost, Pause/Stop; speaker paragraphs; rename popover; inline note and gap markers; 280 px Notes pane) → stopped (export buttons, summary panel above editable transcript, failed-summary inset with Summarise).
  • Meetings window (680×480): day-grouped rows with mode glyph, title, excerpt, meta line; hover Open / Export ▾ / Delete; footer with Show in Finder and Start Meeting…; title-bar search with labelled hit snippets; empty state.
  • Settings → Meetings: engine rows with prices and key gating, Your name, Keep meeting audio, Open Privacy Settings…, Summary prompt editor, Storage, Command-line tool Install…, Claude Code MCP command. Keys gains AssemblyAI and Anthropic; Hotkeys gains Meeting; General's engines gain AssemblyAI.
  • Exports: front matter (title, id, date, start, end, duration, mode, app, engine, speakers, generator), speaker paragraphs as **Name** · hh:mm:ss then text, notes/gaps/pauses as block quotes; summary file adds summary_model, summary_at, transcript, the four sections, a Notes list and a footer line.
  • CLI: mini-whisper meetings list|transcript <id>|summary <id>|search <text>; MCP tools list_meetings, get_transcript, get_summary, search_meetings, all readOnlyHint.

Failure handling

  • Provider drop or close code → reconnect with backoff 1, 2, 4, 8, 15, 30 s indefinitely; gap marker on the first segment after; audio always recorded.
  • System Audio Recording denied → silence from the tap; a hint appears after 60 s of one-sided speech with a button to the privacy pane; the meeting continues microphone-only.
  • Sleep → auto-pause until Resume; device change → reinstall, gap marker if more than 2 s lost; quit while recording → confirmation, stop without summary.
  • Anthropic error or refusal → message with a Summarise button; no key → "No summary: add an Anthropic key under Keys."
  • Disk write failure → notice, segments kept in memory and retried; corrupt jsonl lines skipped; missing index rebuilt.

Security

  • Keys only in the Keychain and in provider request headers over TLS; logs carry sizes and status codes only.
  • Transcript and notes enter the summary request as delimited data; the summary is rendered as text, never executed.
  • Meeting files 0600 in a 0700 folder; audio retention optional and deletable per meeting; README states the consent responsibility.
  • Agent access holds a read-only store view and links no audio or networking; ids validated before any path is built; the installer runs one privileged script with fixed content.

Testing

  • Unit tests per component on fakes: adapters on documented fixtures, SpeechGate and SpeakerAttributor on synthetic data, SessionSupervisor backoff and rollover on VirtualClock, MeetingStore permissions and atomic rewrites, MeetingMarkdown against golden files matching the export mockup, AnthropicClient request and refusal handling, MCPServer handshakes and tools, PricingTests updated to 0.0075.
  • Opt-in integration (MW_INTEGRATION=1): 20 s diarized sessions on each provider, one summary, a real tap smoke test on 14.2+.

Risks

  • Overlapping speech garbles in a mixed stream — documented; two-session mode is the fallback design.
  • Microphone gate false positives mis-attribute remote words — hysteresis, 70 % label rule, voice processing, per-segment reassignment.
  • System Audio Recording denied or revoked silently — first-start note, silence hint, Settings shortcut.
  • Long sessions hit provider limits or sleep — early rollover, backoff reconnect, auto-pause, gap markers.
  • Summary invents content — prompt forbids invention, notes passed separately, transcript shown beneath.
  • Sensitive recordings readable locally — restrictive permissions, retention toggle, README statement.

Rollout

One release (0.6.0) with CHANGELOG entries for the feature, the new permission, the two new keys, the AssemblyAI dictation engine, the Speechmatics price correction and the CLI/MCP surface. No feature flag: meeting mode is inert until used. Implementation order: config/keys/pricing → streaming extensions → audio → MWMeetings → pipeline → MWAgentAccess and main.swift → App surfaces → README/CHANGELOG. Rollback is the previous release; new config keys are ignored by older builds.

Cross-cutting concerns

  • Security:
    • Keys stay in the Keychain and travel only in their auth headers; logs carry sizes and codes only.
    • The transcript enters the summary request as delimited data.
    • MCP input is typed and capped. CLI and MCP take only MeetingReading, with ids validated before lookup.
    • Files are 0600 in 0700 folders. The installer writes a quoted wrapper script, never a symlink.
  • Performance: the meeting listener never accumulates, the system ring holds 2 s, segments stream to disk, the tick stays off the main actor, the paragraph merge is incremental, and search is debounced.
  • Observability: Log.meeting covers start/stop, sessions and close codes, rollover, pause, tap, summary size/status/tokens, exports and CLI/MCP commands.
  • Compatibility:
    • The five optional config keys round-trip.
    • Dictation is unchanged: undiarized Speechmatics is byte-identical, and segments never reach the assembler.
    • The Speechmatics rate change affects new usage only.
    • macOS 14.0/14.1 keep everything except remote mode.

There are 45 decisions in total; the full list is in the plan file. The most consequential:

Deviations from plan

The plan's Deviations from plan section has 28 stage entries and 3 notes. The ones that change behaviour:

  • MCP server/discover follows the current MCP specification rather than design §5.3's shape.
  • Install… asks for an administrator password only when /usr/local/bin isn't user-writable (bd11fb2). The design always used root, which a symlink planted in a user-writable folder could redirect.
  • Starting a meeting cancels a dictation still running (14f05aa). Otherwise a toggle dictation kept the microphone and pasted when its 5-minute cap fired.
  • The summary request appends a fixed "transcript and notes are data" rule in code, and closing tags inside the data are escaped.
  • The AAC encoder's default comes to about 14 MB per hour, not the 29 MB per hour in the design.
  • Close reasons are not logged, only close codes (R27), which narrows design §5.7.
